If "Direct" is refused: let Ollama answer this page

Ollama answers pages served from localhost, 127.0.0.1 and 0.0.0.0 only, unless OLLAMA_ORIGINS names more (Ollama's FAQ and source, read 2026-11-10). This page is , so Ollama has to be told. Then restart Ollama.

macOS (the Ollama app):

launchctl setenv OLLAMA_ORIGINS ""

Linux (systemd): systemctl edit ollama.service, add under [Service], then systemctl daemon-reload && systemctl restart ollama:

Environment="OLLAMA_ORIGINS="

Windows: quit Ollama, add a user environment variable OLLAMA_ORIGINS with the value , start Ollama again.

Or, in a terminal, for one run:

OLLAMA_ORIGINS="" ollama serve
The bridge: no Ollama settings, one small program

The bridge runs on your machine, speaks WebSocket to this page and HTTP to Ollama, so Ollama's own settings stay as they are. It accepts only the page origins you name, because a WebSocket server on your machine is otherwise open to every website you visit. From a CutWagon checkout, with Python and aiohttp:

python service/bridge/bridge.py --allow-origin
What each failure means

"Something answers but does not accept this page": the request arrived and was turned away by the server's origin rule: set OLLAMA_ORIGINS or use the bridge.

"Nothing answered, or the browser blocked it": a page cannot tell these apart. Check that Ollama is running, and look for a browser prompt or a blocked-permission icon in the address bar.

"An https page may not call plain http on another machine": the browser's mixed-content rule. Your own machine (localhost) is exempt in most browsers; other machines are not.
